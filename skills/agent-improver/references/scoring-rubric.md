# エージェント定義 スコアリング基準

各エージェント定義ファイル (`.claude/agents/*.md`) を以下の 6 軸・100 点満点で評価する。

## 1. Role Clarity（責務の明確さ）— 20 点

エージェントの役割・責務範囲が明確に定義されているか。

| 点数 | 基準 |
|---|---|
| 18-20 | 役割が1文で要約され、Generator/Evaluator/Planner の位置づけが明示。担当フェーズが列挙され、他エージェントとの境界が明確 |
| 13-17 | 役割は記載されているが、位置づけや境界が暗黙的 |
| 7-12 | 役割の記載が曖昧。「コードを書く」程度の汎用的な表現 |
| 0-6 | 役割の定義がない、またはフェーズとの対応が不明 |

チェックポイント:
- [ ] Generator / Evaluator / Planner のいずれかが明示されている
- [ ] 担当するフェーズ（plan, execute, review 等）が明記されている
- [ ] 何を「しない」かが明確（責務の境界）
- [ ] プロンプトで渡される情報（ジョブ ID・body 等）が記載されている

## 2. Tool Selection（ツール構成）— 15 点

役割に対して必要十分なツールが `tools:` フロントマターで指定されているか。

| 点数 | 基準 |
|---|---|
| 14-15 | 役割に必要なツールが過不足なく指定。Generator-Evaluator 分離のツール制約を遵守 |
| 10-13 | 概ね適切だが、軽微な過不足がある |
| 5-9 | 不要なツールが含まれている、または必須ツールが欠落 |
| 0-4 | tools フロントマターがない、または役割と大きく乖離 |

チェックポイント:
- [ ] `tools:` がフロントマターで定義されている
- [ ] Evaluator エージェントに Write/Edit が含まれていない（分離違反）
- [ ] Generator エージェントが十分な編集ツールを持っている
- [ ] 調査系エージェントに Read/Grep/Glob 等の検索ツールがある
- [ ] 不要なツール（役割で使用しないもの）が含まれていない

## 3. Prompt Quality（指示の品質）— 20 点

エージェントへの指示が具体的で、再現性のある行動を引き出せるか。

| 点数 | 基準 |
|---|---|
| 18-20 | 番号付きの段階的手順。各ステップの入力・出力が明確。フェーズ別の具体的な行動が定義 |
| 13-17 | 手順はあるが一部が曖昧。フェーズ別の差異が不十分 |
| 7-12 | 箇条書きレベルの指示。手順の順序や依存が不明確 |
| 0-6 | 指示が汎用的すぎる、または記載が極めて少ない |

チェックポイント:
- [ ] フェーズごとに異なる行動が定義されている（該当する場合）
- [ ] 各ステップで何をするかが具体的（「調査する」→「git diff で変更を把握する」）
- [ ] 成果物が各フェーズで明記されている
- [ ] ジョブ body のどのセクションを参照すべきか指示がある
- [ ] エッジケース（失敗時、情報不足時）の対応が記載されている

## 4. Output Contract（出力契約）— 15 点

エージェントの出力形式が明確に定義されているか。

| 点数 | 基準 |
|---|---|
| 14-15 | result の取りうる値が列挙。message のフォーマットがテンプレートで示されている。成功/失敗それぞれの出力例あり |
| 10-13 | result/message は定義されているが、フォーマットが曖昧 |
| 5-9 | 出力形式の記載が部分的。result のみ、または message のみ |
| 0-4 | 出力形式の定義がない |

チェックポイント:
- [ ] `result:` の取りうる値が明記（completed/failed, approved/rejected 等）
- [ ] `message:` の期待フォーマットが示されている
- [ ] 成功時と失敗時それぞれの出力パターンが明確
- [ ] run-job スキルが解釈可能な形式になっている

## 5. Guard Rails（安全柵）— 15 点

エージェントがやってはいけないこと、境界条件が明示されているか。

| 点数 | 基準 |
|---|---|
| 14-15 | 禁止事項が「ルール」セクションで明示。役割の境界を超える行動が具体的に列挙。失敗時の対処も記載 |
| 10-13 | 主要な禁止事項はあるが、一部が暗黙的 |
| 5-9 | 禁止事項の記載が少ない。境界が曖昧 |
| 0-4 | ルールセクションがない、または「良いコードを書く」程度 |

チェックポイント:
- [ ] 「ルール」または同等のセクションがある
- [ ] 役割外の作業の禁止が明記されている（例: Evaluator は編集しない）
- [ ] スコープ外の変更（リファクタ、コメント追加等）の禁止が明記
- [ ] 失敗時の振る舞いが定義されている（エラーを握りつぶさない等）
- [ ] セキュリティに関する注意事項がある（該当する場合）

## 6. Consistency（整合性）— 15 点

他のエージェント定義との用語・フォーマット・構造の一貫性。

| 点数 | 基準 |
|---|---|
| 14-15 | 全エージェントで同一のセクション構造。用語が統一。フロントマターの形式が一貫 |
| 10-13 | 大部分は一貫しているが、軽微な不整合がある |
| 5-9 | セクション構造が異なる、用語が不統一 |
| 0-4 | 他エージェントとの整合性がほぼない |

チェックポイント:
- [ ] フロントマターのキー（name, description, tools, model）が全エージェントで統一
- [ ] セクション見出しの構造が一貫（例: フェーズ別の行動 → ルール → 返却値）
- [ ] 用語の統一（Generator/Evaluator, result/message 等）
- [ ] description の粒度が揃っている
- [ ] 日本語/英語の混在ルールが統一されている

## 警告サイン（減点対象）

以下のパターンは対応する軸で減点し、レポートで明示的に警告する:

| 警告サイン | 関連する軸 | 影響 |
|---|---|---|
| Evaluator に Write/Edit 付与 | Tool Selection | -5 pt + 警告 |
| result/message 形式なし | Output Contract | -10 pt + 警告 |
| フェーズ別の行動定義なし | Prompt Quality | -8 pt + 警告 |
| body 参照手順の欠落 | Prompt Quality | -5 pt + 警告 |
| 禁止事項セクションなし | Guard Rails | -8 pt + 警告 |
| description が 1 行未満 | Consistency | -3 pt + 警告 |
| 汎用的すぎる指示 | Prompt Quality | -5 pt + 警告 |
