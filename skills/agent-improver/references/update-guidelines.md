# エージェント定義の更新ガイドライン

改善提案を適用する際の判断基準と注意事項。

## 追加すべき情報

### 必ず追加する（スコアに直結）

- **フェーズ別の行動定義**: ワークフローで使用されるフェーズに対応する具体的手順
- **返却値セクション**: result の値と message のフォーマット
- **ルールセクション**: 役割外の作業の禁止事項
- **body 参照手順**: ジョブ body のどのセクションから何を読み取るか

### 可能なら追加する（品質向上）

- **失敗時の振る舞い**: エラー発生時に何を返すか
- **コンテキストリセット対応**: フェーズ遷移で情報が失われる前提の設計
- **自己検証ステップ**: execute フェーズでの Acceptance Criteria 自己チェック

## 追加すべきでない情報

- **汎用的なベストプラクティス**: 「DRY 原則に従う」等、プロジェクト固有でない指示
- **IDE やツールの使い方**: エージェントが知っている基本操作
- **コーディングスタイル**: CLAUDE.md やプロジェクト設定で管理すべき内容
- **他エージェントの責務の説明**: 各エージェントは自身の責務のみ記載
- **冗長な説明**: 1 行で言えることを段落で書かない

## 変更時の注意事項

### フロントマター

- `name`: ファイル名と一致させる（拡張子なし）
- `description`: Claude がこのエージェントを自動起動するか判断する材料。具体的かつ簡潔に
- `tools`: 役割に必要十分なものだけ。追加・削除時は Generator-Evaluator 分離を確認
- `model`: 変更する場合はユーザーに確認を取る

### 本文

- 既存のセクション構造を維持する（見出しレベル、順序）
- 他のエージェントと整合するセクション名を使う
- 日本語で記載する（技術用語・ツール名は英語のまま）

### 整合性チェック

変更適用後に以下を確認する:

1. **他エージェントとの整合**: 同じ概念に異なる用語を使っていないか
2. **スキルとの整合**: run-job スキルが期待する出力形式と一致するか
3. **ハーネス原則との整合**: Generator-Evaluator 分離、コンテキストリセット対応が維持されているか
4. **フロントマターの一貫性**: 全エージェントで同じキーが定義されているか

## 変更の提示方法

改善内容は diff 形式で提示し、変更理由を添える:

```markdown
### [agent-name.md] の改善

**理由**: [なぜこの変更が必要か — スコアリング基準との対応]

変更箇所:
- [変更内容の概要]
```

ユーザーの承認を得てから Edit ツールで適用する。
