# エージェント定義テンプレート

エージェント定義の理想的な構造を示すテンプレート集。
改善提案時の参考として使用する。

## 実装系エージェントテンプレート

```markdown
---
name: agent-name
description: |
  [1-3行の具体的な説明。どのような状況で何をするか。
  Claude がこのエージェントを自動起動する判断材料になる。]
tools: Read, Write, Edit, Glob, Grep, Bash
---

# [エージェント名]

[1-2文の役割概要。コードの作成・編集を担当する実装系エージェント。]

## 作業手順

1. [具体的なステップ — 入力と出力を明記]
2. [具体的なステップ]
3. [具体的なステップ]
4. [自己検証ステップ]
5. 作業内容を要約して返す

## ルール

- [禁止事項1 — 具体的に]
- [禁止事項2 — 具体的に]
- [失敗時の振る舞い]

## 出力形式

[成功時・失敗時それぞれの出力フォーマットを示す]
```

   - **[観点A]**: [具体的なチェック内容]

4. 結果を返す

## ルール

- コードを編集しない（指摘のみ行う）
- [具体的な判断基準]
- 問題がある場合は理由と修正方針を示す

## 出力形式

[検証結果のフォーマットを示す。例:]

## 検証結果

## 追加指摘（あれば）
- 指摘事項と理由
\`\`\`

## アンチパターン（避けるべき定義）

### 曖昧な役割定義

```markdown
# Developer

コードを書くエージェント。
```

問題: 役割の位置づけ不明。担当範囲不明。

### ツール過剰付与

```markdown
---
tools: Read, Write, Edit, Glob, Grep, Bash, Agent, WebFetch, WebSearch
---

# Reviewer
```

問題: 評価系エージェントに Write/Edit が含まれており、読み取り専用であるべき。

### 出力形式なし

```markdown
## 作業内容

1. コードを読む
2. 問題を見つける
3. 報告する
```

問題: 出力形式が未定義。呼び出し元が結果を解釈できない。

### 汎用的すぎるルール

```markdown
## ルール

- 良いコードを書く
- テストを忘れない
```

問題: 判断基準が不明確。具体的な禁止事項がない。
