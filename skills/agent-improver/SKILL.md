# エージェント改善スキル

`.claude/agents/*.md` のサブエージェント定義を評価し、品質改善を支援する。

## 前提知識

ccsquad のハーネスは **Generator-Evaluator 分離** を核とする設計で、サブエージェントは以下の役割を担う:

- **Generator** (developer): plan/execute フェーズでコードを書く
- **Evaluator** (reviewer): review/verify フェーズで評価する
- **Planner** (planner): 曖昧な要求をタスクに分解する

エージェント定義は YAML フロントマター + Markdown 本文で構成される。

## 実行フロー

以下の 5 フェーズを順番に実行する。**フェーズ 3（レポート）は必ずユーザーに表示し、改善実施前に確認を取る。**

### フェーズ 1: Discovery（探索）

`.claude/agents/` 配下のすべての `.md` ファイルを検出する。

確認事項:
- ファイル一覧と各ファイルのフロントマター
- プロジェクトの CLAUDE.md とスキル定義（ハーネスの設計原則を理解するため）
- docs/design-principles.md（状態遷移の設計原則）

### フェーズ 2: Assessment（評価）

各エージェント定義を **6 つの評価軸** で採点する。詳細な基準は [scoring-rubric.md](references/scoring-rubric.md) を参照。

| 評価軸 | 配点 | 概要 |
|---|---|---|
| Role Clarity | 20 pt | 責務の明確さ、Generator/Evaluator の分離 |
| Tool Selection | 15 pt | 役割に必要十分なツール構成 |
| Prompt Quality | 20 pt | 指示の具体性・再現性・段階的な手順 |
| Output Contract | 15 pt | 出力形式・result/message の定義 |
| Guard Rails | 15 pt | 禁止事項・境界条件の明示 |
| Consistency | 15 pt | 他エージェントとのフォーマット・用語の整合性 |

**合計 100 点**。グレードは以下:

| グレード | 点数 | 意味 |
|---|---|---|
| A | 90-100 | 包括的で一貫性があり、即座に運用可能 |
| B | 70-89 | 良好だが軽微な改善点あり |
| C | 50-69 | 基本的だが重要な情報が欠落 |
| D | 30-49 | 不十分、大幅な改善が必要 |
| F | 0-29 | 不完全または著しく不整合 |

### フェーズ 3: Reporting（レポート）

評価結果をユーザーに報告する。**改善を行う前に必ずこのレポートを提示する。**

出力フォーマット:

```markdown
## エージェント品質レポート

### 全体サマリー
- 評価対象: N ファイル
- 平均スコア: XX/100 (グレード X)

### ファイル別スコア

#### agent-name.md — XX/100 (グレード X)

| 評価軸 | スコア | コメント |
|---|---|---|
| Role Clarity | XX/20 | ... |
| Tool Selection | XX/15 | ... |
| Prompt Quality | XX/20 | ... |
| Output Contract | XX/15 | ... |
| Guard Rails | XX/15 | ... |
| Consistency | XX/15 | ... |

**改善提案:**
1. [具体的な改善点と理由]
2. [具体的な改善点と理由]

### 重要な指摘事項
- [クリティカルな問題があればここに記載]
```

### フェーズ 4: Proposals（提案）

各エージェント定義に対し、スコアの低い軸を中心に具体的な改善案を提示する。

提案の原則:
- **具体的であること**: 「もっと詳しく書く」ではなく、追加すべき内容のドラフトを示す
- **最小限の変更**: 既存の良い部分は保持し、不足部分のみ補う
- **プロジェクト文脈に沿う**: ハーネスの設計原則（Generator-Evaluator 分離、コンテキストリセット等）との整合性を確認する

### フェーズ 5: Implementation（実装）

ユーザーの承認を得た改善案を適用する。

- 変更は diff 形式で明示してから適用する
- フロントマターと本文の整合性を維持する
- 変更後に他エージェントとの整合性が崩れていないか確認する

## 警告サイン（自動検出）

以下のパターンを検出した場合、レポートで明示的に警告する:

- **ツール過剰付与**: Evaluator に Write/Edit が付与されている（Generator-Evaluator 分離違反）
- **出力形式未定義**: result/message の形式が記載されていない
- **フェーズ未対応**: ワークフローで使用されるフェーズが行動定義に含まれていない
- **汎用的すぎる指示**: 「良いコードを書く」等の非具体的な記述
- **コンテキストリセット非対応**: body からの情報読み取り手順が欠落（次フェーズで情報が失われる）
- **フロントマター不備**: name, description, tools, model のいずれかが欠落
- **description が空または汎用的**: モデル自動起動の判断材料にならない description
