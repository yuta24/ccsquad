# エージェント改善スキル

`.claude/agents/*.md` のサブエージェント定義を評価し、品質改善を支援する。

## 前提知識

Claude Code のサブエージェントは YAML フロントマター + Markdown 本文で構成される。
Agent ツールの `subagent_type` で指定され、専門的なタスクを担当する。

典型的な役割パターン:
- **実装系**: コードの作成・編集を行うエージェント
- **評価系**: コードレビューや品質チェックを行うエージェント（読み取り専用）
- **調査系**: コードベースの探索やリサーチを行うエージェント
- **計画系**: 要件整理やタスク分解を行うエージェント

## 実行フロー

以下の 5 フェーズを順番に実行する。**フェーズ 3（レポート）は必ずユーザーに表示し、改善実施前に確認を取る。**

### フェーズ 1: Discovery（探索）

`.claude/agents/` 配下のすべての `.md` ファイルを検出する。

確認事項:
- ファイル一覧と各ファイルのフロントマター
- プロジェクトの CLAUDE.md（プロジェクト固有の規約やコンテキストを理解するため）
- エージェントを呼び出しているスキルや設定（エージェントの使われ方を理解するため）

### フェーズ 2: Assessment（評価）

各エージェント定義を **6 つの評価軸** で採点する。詳細な基準は [scoring-rubric.md](references/scoring-rubric.md) を参照。

| 評価軸 | 配点 | 概要 |
|---|---|---|
| Role Clarity | 20 pt | 責務の明確さ、役割の位置づけ |
| Tool Selection | 15 pt | 役割に必要十分なツール構成 |
| Prompt Quality | 20 pt | 指示の具体性・再現性・段階的な手順 |
| Output Contract | 15 pt | 出力形式の定義 |
| Guard Rails | 15 pt | 禁止事項・境界条件の明示 |
| Consistency | 15 pt | 他エージェントとのフォーマット・用語の整合性 |

**合計 100 点**。グレードは以下:

| グレード | 点数 | 意味 |
|---|---|---|
| A | 90-100 | 包括的で一貫性があり、即座に運用可能 |
| B | 70-89 | 良好だが軽微な改善点あり |
| C | 50-69 | 基本的だが重要な情報が欠落 |
| D | 30-49 | 不十分、大幅な改善が必要 |
| F | 0-29 | 不完全または著しく不整合 |

### フェーズ 3: Reporting（レポート）

評価結果をユーザーに報告する。**改善を行う前に必ずこのレポートを提示する。**

出力フォーマット:

```markdown
## エージェント品質レポート

### 全体サマリー
- 評価対象: N ファイル
- 平均スコア: XX/100 (グレード X)

### ファイル別スコア

#### agent-name.md — XX/100 (グレード X)

| 評価軸 | スコア | コメント |
|---|---|---|
| Role Clarity | XX/20 | ... |
| Tool Selection | XX/15 | ... |
| Prompt Quality | XX/20 | ... |
| Output Contract | XX/15 | ... |
| Guard Rails | XX/15 | ... |
| Consistency | XX/15 | ... |

**改善提案:**
1. [具体的な改善点と理由]
2. [具体的な改善点と理由]

### 重要な指摘事項
- [クリティカルな問題があればここに記載]
```

### フェーズ 4: Proposals（提案）

各エージェント定義に対し、スコアの低い軸を中心に具体的な改善案を提示する。

提案の原則:
- **具体的であること**: 「もっと詳しく書く」ではなく、追加すべき内容のドラフトを示す
- **最小限の変更**: 既存の良い部分は保持し、不足部分のみ補う
- **プロジェクト文脈に沿う**: プロジェクトの CLAUDE.md や既存のエージェント定義と整合性を保つ

### フェーズ 5: Implementation（実装）

ユーザーの承認を得た改善案を適用する。

- 変更は diff 形式で明示してから適用する
- フロントマターと本文の整合性を維持する
- 変更後に他エージェントとの整合性が崩れていないか確認する

## 警告サイン（自動検出）

以下のパターンを検出した場合、レポートで明示的に警告する:

- **ツール過剰付与**: 評価系エージェントに Write/Edit が付与されている（読み取り専用であるべき）
- **出力形式未定義**: エージェントの出力形式やフォーマットが記載されていない
- **汎用的すぎる指示**: 「良いコードを書く」等の非具体的な記述
- **フロントマター不備**: name, description, tools のいずれかが欠落
- **description が空または汎用的**: モデルの自動起動判断に使えない description
- **役割の境界が不明確**: 何をして何をしないかが定義されていない
